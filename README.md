Part-A
I solved the Subarray Sums II problem using prefix sums and a hash map to count the number of subarrays whose sum is equal to the given target (x). Instead of checking every possible subarray, which would take (O(n^2)) time, I maintained a running prefix sum and stored the frequency of previously encountered prefix sums in a hash map. For each element, I calculated the current prefix sum and checked whether the difference between the current prefix sum and the target (x) existed in the map. If it existed, its frequency represented the number of subarrays ending at the current position whose sum was equal to (x), so I added that frequency to my answer. After checking, I updated the frequency of the current prefix sum in the map. I initially stored the prefix sum 0 with frequency 1 to handle subarrays starting from the beginning of the array. This approach allowed me to solve the problem efficiently without generating every possible subarray.
Time Complexity: (O(n)) on average, because each element requires a constant number of hash map operations.
Space Complexity: (O(n)), because the hash map can store up to (n+1) distinct prefix sums.

I solved the Movie Festival problem using a greedy algorithm because my goal was to watch the maximum number of movies without overlapping their timings. First, I stored the starting and ending times of all movies and sorted them based on their ending times in ascending order. I chose this sorting strategy because selecting the movie that finishes earliest leaves as much time as possible for the remaining movies. After sorting, I selected the first movie and stored its ending time. I then iterated through the remaining movies and selected a movie only if its starting time was greater than or equal to the ending time of the previously selected movie. Whenever I selected a movie, I updated the last ending time and increased my movie count. By following this greedy strategy, I maximized the number of non-overlapping movies without checking every possible combination.
Time Complexity: (O(nlog n)), because sorting the movies takes (O(nlog n)) time and selecting movies takes (O(n)) time.
Space Complexity: (O(n)) to store the starting and ending times of the movies, excluding any additional space used internally by the sorting algorithm.

I solved the Factory Machines problem using binary search on the minimum time required to produce the target number of products. Since all machines work simultaneously, I calculated the total number of products that could be manufactured within a given time (t) by adding (t/k_i) for each machine, where (k_i) represents the time taken by that machine to produce one product. Instead of checking every possible time value, I established a search range with a lower bound of zero and an upper bound based on the fastest machine producing all the required products. I then calculated the midpoint of the range and checked whether the machines could collectively produce at least the target number of products within that time. If they could, I stored that time as a possible answer and searched the lower half for a smaller valid time. Otherwise, I searched the upper half for a larger time. I repeated this process until the minimum possible production time was found. This approach was efficient because the feasibility of producing the target number of products is monotonic: if a time is sufficient, any larger time is also sufficient.
Time Complexity: (O(n log U)), where (n) is the number of machines and (U) is the upper bound of the search range.
Space Complexity: (O(1)) auxiliary space, because I only needed a fixed number of variables for binary search and product counting, excluding the array storing machine times.

Part-B
Brute Force Approach
I initially approached the Subarray Sums II problem using the brute force method, where I considered every possible subarray and calculated its sum to check whether it was equal to the target value (x). I used two nested loops, with the outer loop selecting the starting index and the inner loop selecting the ending index. For each pair of indices, I calculated the sum of the elements within that subarray and incremented the answer whenever the sum matched the target. Although this approach was simple to understand and implement, it was inefficient because there were (O(n^2)) possible subarrays, and calculating each subarray's sum separately could take up to (O(n)) time. Therefore, the overall time complexity was (O(n^3)). I could improve this slightly by maintaining a running sum in the inner loop, which avoids recalculating the sum of each subarray from scratch and reduces the time complexity to (O(n^2)). However, this was still too slow for large input sizes.
Time Complexity: (O(n^2)) with a running sum, or (O(n^3)) if every subarray sum is recalculated from scratch.
Space Complexity: (O(1)), because I only needed a few variables to track the indices, current sum and answer.


Optimized Approach
I optimized my solution using prefix sums and a hash map to count the number of subarrays whose sum equals the target value (x). Instead of generating every possible subarray, I maintained a running prefix sum representing the sum of all elements from the beginning of the array up to the current position. If the current prefix sum is (P), a previous prefix sum of (P-x) indicates that the elements between those two prefix positions have a sum equal to (x). Therefore, for every element, I calculated the current prefix sum and checked how many times (P-x) had already appeared in the hash map. I added that frequency to my answer and then updated the frequency of the current prefix sum. I initialized the frequency of prefix sum zero to one so that subarrays beginning at index zero were counted correctly. This approach allowed me to count valid subarrays without explicitly generating them, making the solution much faster.
Time Complexity: (O(n)) on average, because each element requires a constant number of hash map operations.
Space Complexity: (O(n)), because the hash map can store up to (n+1) distinct prefix sums.
